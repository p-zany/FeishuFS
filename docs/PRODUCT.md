# FeishuFS 产品定义

## 1. 产品目标

FeishuFS 将一个飞书/Lark 知识库以本地只读文件系统的形式挂载，使编辑器、搜索工具、脚本和 AI 工具能用普通文件 API 浏览知识库，而不需要理解飞书 OpenAPI。

用户只需要提供：

1. 知识库空间内**任意一个文档**的链接（知识库空间本身没有可分享的链接）；
2. 一个本地挂载点；
3. 有权访问该知识库的空间与应用凭证。

挂载范围是该文档所在的**整个知识库空间**，而不只是该文档的子树。文档链接只作为定位空间的入口，不会改变挂载根。

首个版本支持 Linux 与 Windows，基于 Rust、`openlark-docs 0.20.0` 和 `fsk`。

## 2. 核心用户流程

```text
配置应用凭证
  → inspect 验证链接、权限和目录映射
  → mount 挂载
  → 用编辑器 / shell / 搜索工具只读访问
  → Ctrl-C 安全卸载
```

推荐命令形态：

```bash
export FEISHU_APP_ID=cli_xxx
export FEISHU_APP_SECRET=xxx

feishufs inspect 'https://example.feishu.cn/wiki/wikcnxxx'
feishufs mount 'https://example.feishu.cn/wiki/wikcnxxx' ./mnt
```

目录刷新完成后的等待间隔由 `--refresh-interval 60s` 控制；正文与附件缓存 TTL 独立由 `--content-ttl 60s` 控制。内容失败冷却默认 `--content-retry-interval 5s`。

## 3. 文件系统映射

挂载根是知识库空间目录。空间内的每个节点按**有没有子页面**决定形态：

- **有子页面的节点**映射为目录，普通文档正文放在该目录的 `index.*`，子页面放在同一目录内；
- **没有子页面的普通文档**直接映射为文件，不额外包一层目录；
- `sheet` / `bitable` 的每个工作表 / 数据表各映射为一个 `标题.<子表名>.csv`；有子页面时放在 `标题/` 内，没有子页面时在当前目录并列，不额外创建目录；
- 空间根目录只有子节点，没有 `index.*`（空间本身没有正文）。

```text
<mountpoint>/            ← 整个知识库空间
├── 快速开始/            ← 有子页面的文档
│   ├── index.md
│   ├── API 说明.md      ← 没有子页面的文档
│   └── 常见问题/
│       └── index.md
├── 数据报表.收入.csv    ← 没有子页面的表格，各子表并列
├── 数据报表.支出.csv
└── 附件.pdf
```

普通叶子文件由标题加内容扩展名构成；标题已经带相同扩展名时不重复追加（标题 `Manual.PDF` → `Manual.PDF`）。表格统一使用 `标题.<子表名>.csv`，无论子表数量多少，都不使用 `index.csv` 或 XLSX。

### 3.1 节点规则

同一节点在“有子页面”和“没有子页面”两种状态下形态不同，因此目录/文件身份由本次快照的实际子节点决定：

| 飞书对象类型 | 有子页面 | 没有子页面 | 获取方式 |
| --- | --- | --- | --- |
| `docx` | `标题/index.md` | `标题.md` | Docs AI Fetch API 读取 XML，由 Rust 转为 Markdown |
| `doc`（旧版） | `标题/index.docx` | `标题.docx` | 导出任务 |
| `sheet` | `标题/标题.<子表名>.csv`（每个工作表一份） | `标题.<子表名>.csv`（每个工作表一份） | 工作表清单 + 带 `sub_id` 的 CSV 导出任务 |
| `bitable` | `标题/标题.<子表名>.csv`（每个数据表一份） | `标题.<子表名>.csv`（每个数据表一份） | 完整分页的数据表清单 + 带 `sub_id` 的 CSV 导出任务 |
| `file` | `标题/index.<安全扩展名>` | `标题.<安全扩展名>` | 原文件直接下载 |
| 其他 / 暂不支持 | `标题/index.md` | `标题.md` | 生成说明、对象类型和云端链接 |
| 空间根（仅挂载根） | `<空间名>/` 本身 | — | 无正文 |

不伪造无法可靠转换的内容；遇到暂不支持的类型时，用户仍能看到节点及原因。

> 表格转换的实施状态与信息保留边界见第 10.4 节。子表清单为空时，节点生成 Markdown 说明（有子页面时为 `index.md`，否则为 `标题.md`），不伪造 CSV。

### 3.1.1 文档内链接

飞书文档正文里指向**本次挂载子树内**节点的链接，会改写成基于文件系统的相对 Markdown 链接，使挂载内容在本地编辑器、静态站点生成器或 `grep`/`ripgrep` 导航时保持可用。

- 将 `docx` 的结构化文档引用转为标准 Markdown 链接，再只改写已知挂载目标；字符规范化遵循第 3.1.2 节，不通过全局替换改变正文结构。
- 目标解析支持 `wiki`、`docx`、`doc`、`sheet`、`bitable`、`file` 等官方文档链接；按节点 token 与 `obj_token` 建立索引。
- 输出相对于当前 `index.*` 的路径，并用尖括号包裹（如 `[API](<../指南/API 说明/index.md>)`），使空格等字符无需转义。
- 表格链接中的 `?sheet=<ID>` / `?table=<ID>` 选择对应 CSV；未知子表保持云端链接。不指定子表时，指向按子表 ID 排序的首个 CSV，有无子页面均遵循此规则。
- 目标名中的 `%` 与 `#` 会被百分号转义；原链接 fragment 保留（`#heading`），跟踪类 query（如 `?from=copy`）丢弃。
- 指向子树外、非飞书域名或未知节点的链接保持原样，不会产生死链替换。
- Markdown 围栏代码块、缩进代码块和行内代码中的示例链接一律不改写。
- 目录刷新后会用缓存的原始 Markdown 重新渲染链接，因此云端改名、移动节点后链接会跟随新路径，无需重新下载正文。

### 3.1.2 结构内容、字符与画板（本轮成功路径）

本轮只落实接口成功、资源可读取时的转换与挂载路径。不修改已有单文件错误处理；新增资源的失败恢复与一致性策略须先讨论，见第 3.1.3 节。

- `docx` 通过 `POST /open-apis/docs_ai/v1/documents/{token}/fetch` 读取 XML；该 POST 是只读内容读取，不创建或修改云文档。
- 使用现有 OpenLark 鉴权和 Transport，自定义该版本 SDK 尚未封装的请求与响应；不依赖 `lark-cli` / `feishu-cli` 可执行文件。
- 以 XML 的节点顺序及嵌套结构渲染正文，不将 Markdown 与另一份块数据做文本锚点或模糊对齐。
- 保留普通段落、标题、强调、列表、引用、代码及标准链接。无法支持的特殊块保留带说明的结构化原文，不静默丢弃；不承诺完全复现飞书页面布局。
- 对普通文本处理 XML/HTML 字符实体及外层 Markdown 转义，并重新做 Markdown 所需的转义。例如引号恢复为引号，`<服务器IP>` 保持可见的字面占位符，不变成 HTML 标签。代码内容只解开传输层 XML 编码，不对其实体或 Markdown 示例再做规范化；链接目标按独立规则处理。
- 画板若明确带有非空 Mermaid 源码，优先原位输出 `mermaid` 围栏代码块。只保留已有源码，不做 OCR、不从节点箭头反推，也不将任意手绘图伪造为 Mermaid。
- 没有 Mermaid 源码的画板通过只读画板图片下载接口获取，原位生成 Markdown 图片引用；不裁剪白边。
- 图片是挂载文件系统中的只读文件，不引用 `/tmp`、宿主机外部目录或会过期的临时 URL。
- 成功路径原型暂用 `.feishufs-assets/<正文 inode>/<十六进制画板 token>.<实际图片扩展名>` 存放只读资产；这不是已冻结的长期资产布局合同。token 编码避免非法字符与 Windows 大小写碰撞，云端同名目录消歧，不能遮蔽资产目录。
- 资产按需发现：第一次成功读取正文后，才出现该正文的图片目录；叶子文档不因附属资产改为目录，`inspect` 不为发现画板而预取全空间正文。
- 接口和图片下载均成功后，安装正文与资产，生成相对图片链接。新请求出错暂按普通 `Result` 返回给原有处理，不增加专用恢复机制。
- 成功的目录与正文刷新会更新资源索引及相对链接；部分资源失败、旧版本保留、图片格式改变等情形不在本轮新增保证范围内。
- 目录改名、移动或叶子/分支转换后，从缓存原文重新计算图片及文档的相对链接；Windows 投影失效同时覆盖资产路径变化。
- 普通内嵌图片/附件的全面本地化、同步块展开或 draw.io 专用转换尚未实现。独立节点的 CSV 多子表导出已实现，见第 10.4 节。未支持资源保留说明及原始结构，不能宣称已完整转换。

### 3.1.3 待讨论：Fetch 失败与资源一致性

这里只记录问题，不提前选择策略或以测试冻结行为：

- 部分图片失败时：正文是否仍可读？错误显示在哪里？是否允许部分结果？
- 重新获取失败时：旧正文与旧图片如何组合，保留多久，什么时候重试？
- 正文、画板和目录不是同一修订时：需要何种一致性，是否需要整体发布？
- 图片格式或 token 改变、资源消失时：路径与已有引用如何更新？
- 失败冷却、退避、限流及资源总量上限：是否需要，如何配置？
- Windows 本地投影缓存与正在读取的文件如何失效？需要原生验证。

通用内容失败冷却（默认 5 秒，包括首次失败）与目录失败退避已在轮询机制讨论中确认，见第 5 节。其余资源组合、自动补偿、图片格式变化等待及按打开句柄固定内容版本的策略仍待讨论，本轮不修改 FSK 或引入本地文件快照。

### 3.2 文件名规则

- 目录名使用节点标题；普通叶子文件名使用标题加内容扩展名；CSV 使用 `标题.<子表名>.csv`，分别清理标题和子表名，截断时保留两部分及 `.csv` 扩展名。
- 清理 Windows 保留字符、控制字符、尾部空格和点。
- 处理 `CON`、`PRN`、`NUL`、`COM1` 等 Windows 保留名（扩展名前插入下划线，如 `CON.md` → `CON_.md`）。
- 同一目录内的名称按大小写不敏感规则判重。
- 已分配名称在挂载进程内保持稳定；后来出现的重名节点或子表追加短 token / 子表 ID，而不重命名已有节点，消歧后缀放在扩展名前。
- 单个组件限制在 180 个 UTF-8 字节以内，为 Windows 路径长度和消歧后缀留出空间。

## 4. 只读语义

### 4.1 保证

- FeishuFS 不实现任何云端写 API。
- 创建、写入、截断、删除、重命名、修改元数据均返回拒绝。
- 文件和目录权限分别呈现为 `0444` 和 `0555`。
- Linux 挂载同时设置 FUSE `RO`。
- Windows 对 ProjFS 的预删除、预重命名、硬链接和“转为完整文件”通知返回拒绝；未知路径查询返回拒绝以阻止本地创建。

### 4.2 Windows 边界

FSK 在 Windows 上使用 ProjFS。ProjFS 本质上是本地缓存与远端投影的合并视图，而不是完整的 FUSE 等价物。FeishuFS 会使用 FSK 暴露的原生通知尽量实现严格只读，并且绝不把本地变化同步到飞书。当前版本要求挂载点为空；如需复用路径，应先删除旧投影缓存并重新创建目录。

## 5. 刷新与一致性

### 5.1 目录树

- 启动时完整读取文档所属知识库空间的可见节点，固定 `space_id`。输入文档只作为首次定位入口，其删除、权限变化或跨空间移动不改变挂载目标。
- 后台在一轮刷新完成后默认等待 60 秒再读取整座空间，实际周期包含遍历耗时；不重叠、不补跑错过的轮次。
- 完整目录快照（包括节点身份、标题、父子关系与内容请求）没有变化时，不增加修订、不重新渲染缓存正文链接、不全量清理 Windows 投影。
- 目录失败后间隔按基础间隔的 2、4、8 倍退避，最多 8 倍；成功后恢复基础间隔。
- 新增、删除、移动和改名在下一次成功刷新后可见；“从无子页面变为有子页面”会在刷新后把文件变为目录（inode 跟随正文）。
- 刷新失败时继续提供最后一次成功快照，不把短暂网络故障表现为空目录。
- inode 在单次挂载生命周期内不复用。
- 每轮目录遍历还读取所有可见 `sheet` 的工作表清单、`bitable` 的完整分页数据表清单，不导出内容。子表身份和名称属于目录快照；清单失败或子表 ID 不合法 / 重复时，整轮不发布，保留旧快照。子表数量不计入 `--max-nodes` 的知识库节点数。
- 节点列表接口返回 `has_child=false` 时不再请求其子节点，以控制刷新所需请求数；字段缺失时保守地继续请求。

### 5.2 正文与附件

- 内容按需下载，避免启动时导出整座知识库；每个 CSV 带自己的 `sub_id` 独立导出、缓存和失败冷却，inode 由知识库节点与子表 ID 决定。
- 内容 TTL 独立于目录刷新间隔，默认 60 秒。打开或元数据查询检查过期；普通读取不主动检查过期。
- 内容失败默认冷却 5 秒，冷却期内有旧缓存则使用旧内容，无旧缓存则返回 I/O 错误；下一次访问在冷却结束后重试。失败不更新最后成功获取时间，成功清除失败状态。
- 同一 inode 的并发获取去重，不同 inode 最多同时获取 4 份。网络获取不持有全局发布锁，已缓存文件不等待不相关的慢下载。
- 获取期间节点被删除或内容身份改变时，丢弃旧响应，不发布到错误节点；目录与内容发布只用短时锁协调。
- Windows 独立按内容 TTL 检查已缓存文件，按需清理过期投影，避免无目录变化时正文永远不刷新；不为此预取未读取的正文。
- 目前共享缓存不按打开句柄固定版本。其他打开、元数据查询或相对链接重渲染可能改变正在读取的内容；本轮明确不承诺单次打开的严格快照一致性，FSK 与本地快照改造暂缓。

### 5.3 容量和 API 限制

- 默认单文件上限 100 MiB，可配置；正文与资产的合计上限及资产数量限制待讨论，不在本轮新增。
- 默认单次挂载最多 10,000 个知识库节点，可配置。
- Wiki 节点列表接口限制为 100 次/分钟；大知识库可能无法严格在一分钟内完成一次全量遍历，程序会保留旧快照并重试。
- 内容按需获取、同 inode 去重，不同 inode 默认最多 4 份并发；这不是 API 速率限制器。本轮不增加跨进程配额协调或复杂限流。旧 Markdown 接口的 5 次/秒限制不能直接推断为 Docs AI Fetch 接口的限制。

## 6. CLI 合同

### `feishufs inspect`

- 解析链接并验证它属于可识别的飞书/Lark 文档路径。
- 验证凭证、文档所属知识库空间和空间内节点的读取权限。
- 输出将要挂载的整个空间树、对象类型和目标文件名。
- 不创建挂载。

### `feishufs mount`

- 完成与 `inspect` 相同的前置校验。
- 建立只读挂载。
- 前台运行并输出根节点、刷新周期、挂载点和平台后端。
- 收到 Ctrl-C 后停止刷新并安全卸载。

### 凭证

优先从环境变量读取：

- `FEISHU_APP_ID`
- `FEISHU_APP_SECRET`
- 可选 `FEISHU_USER_ACCESS_TOKEN`
- 可选 `FEISHU_API_BASE_URL`

默认不创建包含密钥的配置文件，也不会在日志中输出 secret/token。

## 7. 错误体验

启动失败应给出可执行的信息：

- 链接格式不支持：列出支持的路径类型；
- 链接指向的文档不属于任何知识库空间：提示需要知识库内的文档链接；
- 凭证缺失：指出缺少的环境变量；
- 权限不足：列出所需只读权限和“应用需能访问目标知识库”；
- FUSE / ProjFS 未启用：给出平台安装命令；
- 导出类型不支持：在对应节点生成说明文件，不导致整个挂载失败；
- 后台刷新失败：保留旧快照，只记录结构化警告。

### 7.1 日志

日志分为两个出口，职责不同：

- 应用自身的 CLI、日志和错误标签使用英文；云端标题、正文与原始服务端消息保留原文。中文路径和 Unicode 正文测试数据保留可读原文，不使用 Unicode 转义隐藏。
- **终端**：保持简短，只回答“发生了什么”（含节点 inode 与外层错误描述），可直接阅读或重定向。
- **日志文件**：同一批事件以 `debug`（`-vv` 时为 `trace`）记录，并为每个失败额外记录**完整的错误链**。飞书错误码与响应体只存在于错误链里，因此排障必须看文件。

日志文件合同：

- 默认路径：当前工作目录的 `feishufs.log`，可用 `--log-file <PATH>` 或 `FEISHUFS_LOG_FILE` 覆盖；
- 可用 `--no-log-file` 完全关闭，此时只输出到终端；
- 启动时在终端和文件里都会打印实际使用的**绝对路径**；`mount` 的启动摘要中也会列出；
- 以追加方式写，启动时若文件超过 8 MiB 则轮转为 `<名称>.1`，只保留一份备份；
- 每行带时间、级别、线程名与模块，多线程并发时整行原子写入，不会交错；
- 终端输出非 TTY（重定向/管道）时不带 ANSI 转义；
- 日志文件打不开不致命：只输出一条警告并继续仅用终端；
- 日志不写入刷新后的凭证，也不包含 app secret。

`RUST_LOG` 一旦设置，会同时覆盖两个出口的过滤规则（此时终端与文件同样详细）。

## 8. 非目标

首个版本不包含：

- 本地修改同步回飞书；
- 离线首次挂载；
- 桌面 GUI、托盘或常驻服务；
- 多知识库合并为一个挂载；
- 对文档内所有普通图片和附件做全面本地化（第 3.1.2 节的无 Mermaid 源码画板图片是明确纳入的例外）；
- macOS 发布与签名。

## 9. MVP 验收标准

1. 给定知识库内文档链接和凭证，可解析出所属空间并递归读取整个空间的节点树。
2. 有子页面的节点映射为目录，普通文档正文使用 `index.*`；普通叶子文档映射为同级文件。表格每个子表统一使用 `标题.<子表名>.csv`，分别位于节点目录或父目录。
3. `docx` 能通过新内容接口读取为 Markdown；画板有 Mermaid 源码时保留代码，无源码时以可读取的挂载图片保留原位；附件能原样读取；独立表格逐个子表导出 CSV。
4. 所有通用写操作被拒绝，且没有任何云端写请求。
5. 正文中指向挂载子树内节点的飞书链接被改写为可用的相对本地路径；子树外链接和代码块内容不变。
6. 云端目录变化在下一次成功遍历后可见（默认等待间隔 60 秒，另加遍历耗时）；内容过期后由打开或元数据查询触发更新。失败冷却/退避和正在使用的 Windows 投影可能延迟更新，不承诺严格一分钟上界。
7. API 暂时失败时，已有快照和缓存继续可读。
8. Linux 完成真实 FUSE 挂载冒烟测试。
9. Windows 目标通过编译检查，并有只读通知逻辑的单元测试；原生挂载由 Windows CI / 主机验证。
10. `cargo fmt --check`、`cargo clippy -- -D warnings`、`cargo test` 全部通过。
11. devenv 可重现工具链，进入 shell 自动安装 Git hooks。

## 10. 内容转换需求及实施状态

第 3.1.2 节约定的画板 Mermaid / 图片处理和第 10.4a 节的独立表格多子表 CSV 导出已实现；其他内容保真与资源本地化需求按下述边界记录，不自动视为已完整支持。

### 10.1 同步块视作独立内容块

飞书文档中的同步块按“两个独立的内容块”处理，不做跨位置/跨文档同步。

- 不做跨实例同步。尚未实现源文档读取及同步块展开；新 XML 中的未支持同步块保留结构化占位及说明。
- 待确认：实际同步块的结构、权限和源内容获取方式。

### 10.2 draw.io 等嵌入对象保留为图片

文档中的 draw.io、画板一类对象保留图片形态，不尝试转为文本。

- 本次已授权：无 Mermaid 源码的画板输出挂载内图片；有明确 Mermaid 源码的画板优先代码，见第 3.1.2 节。
- 仍待实施：draw.io 等其他嵌入对象的专用转换及普通内嵌图片的全面本地化。不能把一个画板下载成功推广为所有嵌入类型均已支持。

### 10.3 文本绘图转为 mermaid 代码块

飞书“文本绘图”输出为 Markdown 的 ```` ```mermaid ```` 代码块。

- 已验证新内容接口能在“首页”的画板 XML 中返回 `type="mermaid"` 及源文本，本次直接保留这类已有源码。
- 其他文本绘图组件的源文本类型仍需真实验证；本次不保证未知组件均能转换，不从图片或非 Mermaid 数据生成源码。

### 10.4 表格统一为 CSV / Markdown 表格

#### 10.4a 独立节点：已实现多子表 CSV

- `sheet` / `bitable` 每个子表一份 CSV，统一命名为 `标题.<子表名>.csv`；有子页面时位于 `标题/`，没有子页面时位于父目录。不使用默认 `index.csv` 或 XLSX。
- 使用 SDK 的 sheets 工作表查询和 bitable 数据表列表（完整分页）获取子表 ID 与名称；每轮刷新增加清单请求，但不在启动或 `inspect` 时创建导出任务。隐藏工作表仍列入清单，不自行按隐藏属性过滤。
- 首次访问每个 CSV 时，创建 `file_extension=csv`、`type=sheet/bitable`、`sub_id=<该子表 ID>` 的原生导出任务，轮询完成后下载。保留导出字节、编码、引号与换行，不再自行格式化 CSV。
- 云端子表改名 / 增删、节点改名 / 移动和叶子 / 分支转换在下一次成功目录刷新后可见；子表 ID 不变时 inode 与独立缓存不变，内容对象改变时旧内容身份失效。同名清理后冲突不覆盖已有文件。
- 数据边界是服务端对每个工作表 / 数据表的原生 CSV 导出结果：保留计算结果文本，不保留公式源码、样式、条件格式、图表或布局。多视图和筛选视图不分别导出，不传视图或选择范围；附件字段保留服务端导出的文本 / 名称 / 链接，不额外下载二进制附件。
- 隐藏行列、筛选状态、复杂字段与附件字段的具体 CSV 表示由服务端决定，尚未用真实复杂表格完整核验；不能据此宣称所有这些内容均无损。SDK 请求、完整分页、`sub_id`、下载字节保留和限额已覆盖离线接口测试；目录映射、链接、消歧、缓存与增删改名已覆盖文件系统测试。

#### 10.4b 文档内表格：已有简单 Markdown 转换

简单 XML 表格直接渲染为 Markdown 表格，已覆盖单元测试。合并单元格等未支持结构保留说明与原始 XML；“所有文档表格信息完整”的目标仍未完成真实验证。
