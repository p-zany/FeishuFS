# FeishuFS 产品定义

## 1. 产品目标

FeishuFS 将一个飞书/Lark 知识库以本地只读文件系统的形式挂载，使编辑器、搜索工具、脚本和 AI 工具能用普通文件 API 浏览知识库，而不需要理解飞书 OpenAPI。

用户只需要提供：

1. 知识库空间内**任意一个文档**的链接（知识库空间本身没有可分享的链接）；
2. 一个本地挂载点；
3. 有权访问该知识库的空间与应用凭证。

挂载范围是该文档所在的**整个知识库空间**，而不只是该文档的子树。文档链接只作为定位空间的入口，不会改变挂载根。

首个版本支持 Linux 与 Windows，基于 Rust、`openlark-docs 0.20.0` 和 `fsk`。

## 2. 核心用户流程

```text
配置应用凭证
  → inspect 验证链接、权限和目录映射
  → mount 挂载
  → 用编辑器 / shell / 搜索工具只读访问
  → Ctrl-C 安全卸载
```

推荐命令形态：

```bash
export FEISHU_APP_ID=cli_xxx
export FEISHU_APP_SECRET=xxx

feishufs inspect 'https://example.feishu.cn/wiki/wikcnxxx'
feishufs mount 'https://example.feishu.cn/wiki/wikcnxxx' ./mnt
```

可通过 `--refresh-interval 60s` 调整刷新周期，默认 60 秒。

## 3. 文件系统映射

挂载根是知识库空间目录。空间内的每个节点按**有没有子页面**决定形态：

- **有子页面的文档**映射为目录，正文放在该目录的 `index.*`，子页面放在同一目录内；
- **没有子页面的文档**直接映射为文件，不额外包一层目录；
- 空间根目录只有子节点，没有 `index.*`（空间本身没有正文）。

```text
<mountpoint>/            ← 整个知识库空间
├── 快速开始/            ← 有子页面的文档
│   ├── index.md
│   ├── API 说明.md      ← 没有子页面的文档
│   └── 常见问题/
│       └── index.md
├── 数据报表.xlsx        ← 没有子页面的表格
└── 附件.pdf
```

叶子形态的名称由标题加内容扩展名构成；标题已经带相同扩展名时不重复追加（标题 `Manual.PDF` → `Manual.PDF`）。

### 3.1 节点规则

同一节点在“有子页面”和“没有子页面”两种状态下形态不同，因此目录/文件身份由本次快照的实际子节点决定：

| 飞书对象类型 | 有子页面 | 没有子页面 | 获取方式 |
| --- | --- | --- | --- |
| `docx` | `标题/index.md` | `标题.md` | Docs Content API 转为 Markdown |
| `doc`（旧版） | `标题/index.docx` | `标题.docx` | 导出任务 |
| `sheet` | `标题/index.xlsx` | `标题.xlsx` | 导出任务 |
| `bitable` | `标题/index.xlsx` | `标题.xlsx` | 导出任务 |
| `file` | `标题/index.<安全扩展名>` | `标题.<安全扩展名>` | 原文件直接下载 |
| 其他 / 暂不支持 | `标题/index.md` | `标题.md` | 生成说明、对象类型和云端链接 |
| 空间根（仅挂载根） | `<空间名>/` 本身 | — | 无正文 |

不伪造无法可靠转换的内容；遇到暂不支持的类型时，用户仍能看到节点及原因。

> 本节描述的是**当前实现**。已记录但尚未实现的表格转换变更（`sheet`/`bitable` → CSV、文档内表格 → Markdown 表格）见第 10.4 节，它一旦实现会修改上表。

### 3.1.1 文档内链接

飞书文档正文里指向**本次挂载子树内**节点的链接，会改写成基于文件系统的相对 Markdown 链接，使挂载内容在本地编辑器、静态站点生成器或 `grep`/`ripgrep` 导航时保持可用。

- 只改写在 `docx` 正文 Markdown 中解析出的链接目标，不改动正文文本本身。
- 目标解析支持 `wiki`、`docx`、`doc`、`sheet`、`bitable`、`file` 等官方文档链接；按节点 token 与 `obj_token` 建立索引。
- 输出相对于当前 `index.*` 的路径，并用尖括号包裹（如 `[API](<../指南/API 说明/index.md>)`），使空格等字符无需转义。
- 目标名中的 `%` 与 `#` 会被百分号转义；原链接 fragment 保留（`#heading`），跟踪类 query（如 `?from=copy`）丢弃。
- 指向子树外、非飞书域名或未知节点的链接保持原样，不会产生死链替换。
- Markdown 围栏代码块、缩进代码块和行内代码中的示例链接一律不改写。
- 目录刷新后会用缓存的原始 Markdown 重新渲染链接，因此云端改名、移动节点后链接会跟随新路径，无需重新下载正文。

### 3.2 文件名规则

- 目录名使用节点标题；叶子文件名使用标题加内容扩展名。
- 清理 Windows 保留字符、控制字符、尾部空格和点。
- 处理 `CON`、`PRN`、`NUL`、`COM1` 等 Windows 保留名（扩展名前插入下划线，如 `CON.md` → `CON_.md`）。
- 同一目录内的名称按大小写不敏感规则判重。
- 已分配名称在挂载进程内保持稳定；后来出现的重名节点追加短 token，而不重命名已有节点。
- 单个组件限制在 180 个 UTF-8 字节以内，为 Windows 路径长度和消歧后缀留出空间。

## 4. 只读语义

### 4.1 保证

- FeishuFS 不实现任何云端写 API。
- 创建、写入、截断、删除、重命名、修改元数据均返回拒绝。
- 文件和目录权限分别呈现为 `0444` 和 `0555`。
- Linux 挂载同时设置 FUSE `RO`。
- Windows 对 ProjFS 的预删除、预重命名、硬链接和“转为完整文件”通知返回拒绝；未知路径查询返回拒绝以阻止本地创建。

### 4.2 Windows 边界

FSK 在 Windows 上使用 ProjFS。ProjFS 本质上是本地缓存与远端投影的合并视图，而不是完整的 FUSE 等价物。FeishuFS 会使用 FSK 暴露的原生通知尽量实现严格只读，并且绝不把本地变化同步到飞书。当前版本要求挂载点为空；如需复用路径，应先删除旧投影缓存并重新创建目录。

## 5. 刷新与一致性

### 5.1 目录树

- 启动时完整读取文档所属知识库空间的可见节点。
- 后台默认每 60 秒重新读取整座空间。
- 新增、删除、移动和改名在下一次成功刷新后可见；“从无子页面变为有子页面”会在刷新后把文件变为目录（inode 跟随正文）。
- 刷新失败时继续提供最后一次成功快照，不把短暂网络故障表现为空目录。
- inode 在单次挂载生命周期内不复用。
- 节点列表接口返回 `has_child=false` 时不再请求其子节点，以控制刷新所需请求数；字段缺失时保守地继续请求。

### 5.2 正文与附件

- 内容按需下载，避免启动时导出整座知识库。
- 成功内容缓存默认不超过刷新周期。
- 缓存过期后的首次访问触发重新获取。
- 重新获取失败但存在旧缓存时，继续提供旧内容并记录警告。
- 同一内容的并发首次读取只执行一次下载。

### 5.3 容量和 API 限制

- 默认单文件上限 100 MiB，可配置。
- 默认单次挂载最多 10,000 个知识库节点，可配置。
- Wiki 节点列表接口限制为 100 次/分钟；大知识库可能无法严格在一分钟内完成一次全量遍历，程序会保留旧快照并重试。
- Markdown 内容接口限制为 5 次/秒；内容获取采用按需和串行去重策略。

## 6. CLI 合同

### `feishufs inspect`

- 解析链接并验证它属于可识别的飞书/Lark 文档路径。
- 验证凭证、文档所属知识库空间和空间内节点的读取权限。
- 输出将要挂载的整个空间树、对象类型和目标文件名。
- 不创建挂载。

### `feishufs mount`

- 完成与 `inspect` 相同的前置校验。
- 建立只读挂载。
- 前台运行并输出根节点、刷新周期、挂载点和平台后端。
- 收到 Ctrl-C 后停止刷新并安全卸载。

### 凭证

优先从环境变量读取：

- `FEISHU_APP_ID`
- `FEISHU_APP_SECRET`
- 可选 `FEISHU_USER_ACCESS_TOKEN`
- 可选 `FEISHU_API_BASE_URL`

默认不创建包含密钥的配置文件，也不会在日志中输出 secret/token。

## 7. 错误体验

启动失败应给出可执行的信息：

- 链接格式不支持：列出支持的路径类型；
- 链接指向的文档不属于任何知识库空间：提示需要知识库内的文档链接；
- 凭证缺失：指出缺少的环境变量；
- 权限不足：列出所需只读权限和“应用需能访问目标知识库”；
- FUSE / ProjFS 未启用：给出平台安装命令；
- 导出类型不支持：在对应节点生成说明文件，不导致整个挂载失败；
- 后台刷新失败：保留旧快照，只记录结构化警告。

## 8. 非目标

首个版本不包含：

- 本地修改同步回飞书；
- 离线首次挂载；
- 桌面 GUI、托盘或常驻服务；
- 多知识库合并为一个挂载；
- 对 Markdown 内所有图片和附件做本地重写（见 10.2：若改为处理 draw.io 等嵌入对象，需同时决定是否本地化普通内嵌图片）；
- macOS 发布与签名。

## 9. MVP 验收标准

1. 给定知识库内文档链接和凭证，可解析出所属空间并递归读取整个空间的节点树。
2. 有子页面的文档映射为“目录 + `index.*`”，没有子页面的文档映射为同级文件。
3. `docx` 能读取为 Markdown；附件能原样读取；表格类型能导出读取。
4. 所有通用写操作被拒绝，且没有任何云端写请求。
5. 正文中指向挂载子树内节点的飞书链接被改写为可用的相对本地路径；子树外链接和代码块内容不变。
6. 云端目录变化和内容变化在默认一分钟级缓存窗口后可观察。
7. API 暂时失败时，已有快照和缓存继续可读。
8. Linux 完成真实 FUSE 挂载冒烟测试。
9. Windows 目标通过编译检查，并有只读通知逻辑的单元测试；原生挂载由 Windows CI / 主机验证。
10. `cargo fmt --check`、`cargo clippy -- -D warnings`、`cargo test` 全部通过。
11. devenv 可重现工具链，进入 shell 自动安装 Git hooks。

## 10. 已记录但尚未实现的内容转换需求

本节是产品记录，**当前代码均未实现**。每条末尾给出与现有实现的关系（含已核实的冲突）。

### 10.1 同步块视作独立内容块

飞书文档中的同步块按“两个独立的内容块”处理，不做跨位置/跨文档同步。

- 与现有实现：**无冲突**。当前正文完全来自 Docs Content API 的 Markdown，再按所在文档路径改写链接；同一同步块在不同文档中各渲染一次、各自改写，正好符合“独立内容块”的语义。
- 待确认：Markdown 接口对同步块的输出形态（展开原文 / 占位符 / 省略）尚未用真实文档验证。

### 10.2 draw.io 等嵌入对象保留为图片

文档中的 draw.io、画板一类对象保留图片形态，不尝试转为文本。

- 与现有实现：**取决于语义**。
  - “保持图片语义、不转文本” → 无冲突：当前既不下载也不改写内嵌图片，远程图片 URL 原样保留。
  - “导出为本地图片文件”（如 `assets/xxx.png` 并把正文图片链接指向本地） → **与现有非目标冲突**：第 8 节写了“不把内嵌图片缓存或改写为本地文件”，并且需要新增媒体下载接口、二进制资产命名与刷新/失效策略。
- 需要决策：是否把“内嵌图片本地化”纳入范围；若纳入，应与文档内普通图片一并设计，而不是只处理 draw.io。

### 10.3 文本绘图转为 mermaid 代码块

飞书“文本绘图”输出为 Markdown 的 ```` ```mermaid ```` 代码块。

- 与现有实现：与已声明的保证不冲突，但与当前内容管线**能力不符**：现有实现对正文零解析，完全依赖 Markdown 接口输出。自行生成 mermaid 需要块级数据（docx blocks）与自建渲染，属于新增能力。
- 待确认：Markdown 接口是否已直接输出 mermaid；若已输出，本条退化为验收项而非新功能。

### 10.4 表格统一为 CSV / Markdown 表格

- 10.4a 独立节点：`sheet` 与 `bitable` 都转换为 CSV；不追求公式、条件格式等表达能力，只要求信息完整。
- 10.4b 文档内表格：直接使用 Markdown 表格。

- 10.4a 与现有实现：**直接冲突**。当前合同与实现均为 `sheet`/`bitable` → `标题.xlsx`（有子页面时 `标题/index.xlsx`），走导出任务 xlsx。
- 已核实的事实：导出任务的 `file_extension` 确实支持 `csv`，但 **sheet/bitable 导出 csv 必须传 `sub_id`**（指定工作表或数据表），否则会被参数校验直接拒绝。因此 CSV 方案不是改扩展名，而是把“一个节点一个内容文件”变成“一个节点多个 CSV”。
- 需要决定（属于第 3.1 节契约变更）：
  1. 多工作表/多数据表的命名：默认子表用 `index.csv`、其余并列？还是统一 `标题.<子表名>.csv`？
  2. 子表清单需要额外接口（sheets 元信息查询、bitable 数据表列表，SDK 均有），会给目录刷新增加请求量。
  3. “信息完整”的验收边界：公式与条件格式只保留计算结果文本，但多视图、筛选视图、隐藏行列、附件字段如何取舍必须写清楚。
- 10.4b 与现有实现：**无冲突**，文档内表格已经由 Markdown 接口输出，预期为 Markdown 表格（尚未用真实文档验证）；合并单元格等复杂结构的保真度也需要一并确认。
- 影响面（实现时需同步修改）：第 3.1 节节点规则、README 映射表、`content_spec` 的扩展名映射及相关单元测试。
